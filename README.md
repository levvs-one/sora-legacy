Клиент Sora для старых Windows: Windows 7 SP1, 8.1, 10 и 11 на x86 (на x64 работает через WoW64). Отдельный репозиторий и отдельное поколение; обычный клиент для современных систем — [sora](https://github.com/levvs-one/sora).

## Установка

Требования одной строкой: Windows 7 SP1 или новее, .NET Framework 4.8; установщик сам проверяет .NET и нужные обновления Windows 7 и ставит то, чего не хватает и что может поставить сам. Установка — per-user, без прав администратора, в `%LOCALAPPDATA%\Programs\Sora`.

Готового публичного релиза пока нет: установщик собирается из этого репозитория по рецепту разработки. Полная инструкция, поведение при обновлении и удалении — [docs/install.md](docs/install.md).

## Быстрый старт

1. Запустите клиент.
2. Добавьте ссылку подписки или отдельного сервера — формат определится автоматически.
3. Выберите сервер и подключитесь: режим системного прокси или TUN.

## Состояние поставки

- **Релизы публикуются на GitHub**: [v0.2.4](https://github.com/levvs-one/sora-legacy/releases/tag/v0.2.4) и [v0.2.3](https://github.com/levvs-one/sora-legacy/releases/tag/v0.2.3) — исходники, пакеты Linux, Android APK и описанный ниже комплект поставки Windows.
- **Поставляемый сегодня исполняемый файл — клиент на базе v2rayN** (`sora_<цель>.exe`, например `sora_win7.exe`). Именно он собирается в CI, проходит регрессионные проверки и кладётся в установочный комплект скриптом `legacy/build/Stage-Release.ps1`.
- **Новый клиент** (`legacy/Client`, .NET Framework 4.8, WinForms) собран, входит в репозиторий и проверяется интероп-тестами против настоящей службы ядра, но **в установочный комплект пока не включён**. Смена комплекта — отдельная работа; пока она не сделана, новый клиент пользователю не поставляется.
- **Ссылки `sora://` установщик уже регистрирует**, но сегодня зарегистрированный обработчик — поставляемый v2rayN-клиент, который аргумент `sora://…` не обрабатывает: переход по ссылке пока молча игнорируется. Обработчик, импортирующий подписку из ссылки, — новый клиент; регистрация заработает без изменений, когда комплект переключится на него.
- Совместимость с Windows 7 SP1 и 8.1 **запуском на этих системах ещё не подтверждена**. Поддержка обеспечена конструкцией (клиент на .NET Framework 4.8, Win7-движки, ядро на Windows 7 SDK Go); все проверки выполнены на Linux и современной Windows в CI.

## Возможности

Поставляемый клиент:

- Подписки — отдельными сворачиваемыми секциями на экране серверов: название, описание, лимит трафика, срок действия, обновление и проверка задержки относятся к конкретной подписке.
- Импорт одной строкой: HTTPS-подписки, VMess, VLESS, Trojan, Shadowsocks, SOCKS, Base64, SIP008 и Xray JSON; формат определяется автоматически.
- Проверка задержки — прямым TCP-соединением с адресом сервера.
- Режимы подключения: системный прокси и TUN.
- Журналы с сохранением в UTF-8 и отдельный безопасный диагностический архив без конфигураций и учётных данных.

Ядро и новый клиент (в поставку не входят):

- Ядро — служба на Go (`core/`), контракт `sora.core.v1` версии 1.7; на Windows служба регистрируется как `SoraLegacyCore`. Ядром пользуется новый клиент; поставляемый клиент запускает движки сам.
- Три движка: sing-box, Xray, mihomo. Служба выбирает движок под план подключения; упавший движок перезапускается супервизором с ограниченным бюджетом попыток.
- Протоколы ссылок и подписок: VLESS, VMess (включая классический base64-формат), Trojan, Shadowsocks, SOCKS, HTTP(S)-прокси, Hysteria2, TUIC, WireGuard. Транспорты: TCP, WebSocket, gRPC, HTTP/2, HTTPUpgrade, XHTTP — включая поле `extra` (split-доставка, xmux, padding) в пределах возможностей конкретного движка.
- REALITY, uTLS-отпечатки, ECH. REALITY KeyShare рендерится только для lx-варианта sing-box; на upstream-сборке sing-box эта возможность не заявляется.
- Hysteria2: up/down в мегабитах и port hopping. TUIC: congestion control, по умолчанию BBR.
- Подписки: загрузка только по HTTPS; резервная (fallback) ссылка; переопределения списка серверов — переименования, скрытые серверы, закреплённый порядок. Честная граница: файл переопределений ядро читает и применяет при каждом обновлении подписки, но RPC для его записи в контракте этого поколения нет, поэтому интерфейс запись переопределений пока не предлагает.
- Обфускация загрузчика подписок на уровне соединения: фрагментация ClientHello, подмена SNI (FakeSNI), джиттер задержек записи.
- Kill switch (WFP на Windows, nftables на Linux), TUN, системный прокси.

Чего в этом поколении нет, и документация этого не обещает: 13 RPC основного клиента — среди них `CheckDnsLeaks`, `BenchmarkServers` и `SelectServer`, сетевые профили, цепочки прокси, переопределения подписок по RPC и синхронизация устройств. Контракт этого репозитория — `proto/sora/core/v1/core_control.proto`.

## Безопасность

- Движки проверяются fail-closed: служба сверяет бинари движков с дайджестами из поставляемого `SHA256SUMS`; несовпадение — отказ запуска, а не предупреждение. Обновление ядер из поставляемого клиента сверяет SHA-256 архива с `.dgst`-манифестом релиза до распаковки только для ядер v2fly, v2fly_v5 и Xray. Для SagerNet (v2ray-core), clash и clash_meta такой сверки нет: апстрим не публикует `.dgst` в предсказуемом виде, проверка хеша пропускается, и для этих ядер действует только запрет downgrade. Ядро sing_box из интерфейса не обновляется вовсе.
- Самообновления у самого клиента нет: пункт проверки обновлений интерфейса просто открывает страницу релизов в браузере. Обновление — ручная установка новой версии поверх старой.
- Подписки и секреты ядро хранит в зашифрованном хранилище (AES-256-GCM; ключ на Windows защищён DPAPI). Журнал ядро держит в памяти, секреты в журнал и диагностические архивы не попадают — работает маскирование.
- Телеметрии в ядре нет. Сетевые обращения: загрузка подписок у вашего провайдера и — только по вашему действию в интерфейсе поставляемого клиента — проверка обновлений ядер и геобаз у официальных релизов на GitHub.
- Подписи релизов установщика пока не выпускаются: ключ подписи — действие владельца, до церемонии ключа установщик неподписан.
