# packaging/linux

Пакеты службы ядра для Linux: `.deb`, `.rpm` и пакет Arch Linux, собранные
[nfpm](https://github.com/goreleaser/nfpm) из одного описания `nfpm.yaml`.

## Что ставит пакет

| Путь | Что это |
| --- | --- |
| `/usr/bin/sora-core` | служба ядра |
| `/usr/bin/sora-ctl` | клиент управления службой (статус, импорт, подключение) — см. «Почему на Linux нет GUI» ниже |
| `/usr/lib/sora/engines/` | sing-box, Xray-core, mihomo, `geoip.dat`, `geosite.dat` |
| `/usr/lib/systemd/system/sora-core.service` | unit службы, см. [service/linux](../../service/linux/README.md) |
| `/usr/lib/sysusers.d/sora.conf` | пользователь и группа `sora` |
| `/usr/share/polkit-1/actions/io.github.levvs-one.sora.policy` | доступ к службе для активной локальной сессии |

После установки скрипт создаёт пользователя службы, включает и запускает её.
Управляет службой `sora-ctl` из того же пакета: в активной локальной сессии
доступ к сокету даёт polkit без пароля и без групп, на системах без polkit —
членство в группе `sora`. Обновление перезапускает службу на новой версии.
Удаление останавливает службу и снимает таблицу nftables `sora`, если служба
не успела снять её сама; `purge` (и финальный erase в rpm) дополнительно
удаляет `/var/lib/sora` — хранилище секретов и токен управления не переживают
деинсталляцию. Обычное удаление без purge состояние сохраняет, чтобы
переустановка не теряла подписки.

## Движки

Версии и SHA-256 движков закреплены в [`engines.lock`](../engines/engines.lock).
[`fetch.sh`](../engines/fetch.sh) скачивает их по HTTPS и отказывается собирать
пакет, если сумма хоть одного файла не совпала. Базы geoip и geosite берутся из
архива Xray той же закреплённой версии. После раскладки `fetch.sh` записывает
`SHA256SUMS` с дайджестами извлечённых бинарей — этот манифест упаковывается
рядом с движками (`/usr/lib/sora/engines/SHA256SUMS`), и `sora-core` сверяет по
нему бинари при discovery. Не удаляйте и не правьте его вручную: подпись релизов
(offline minisign-ключ) — за владельцем, см. раздел 9 плана исправлений.

Имя манифеста в поколении legacy — именно `SHA256SUMS`: так его пишет
`fetch.sh`, так его ждёт служба (`core/engine/supervise`). В основном
репозитории sora тот же механизм называется `engines.digests`. Деревья
packaging двух репозиториев не взаимозаменяемы: не копируйте манифест и
пакеты одного поколения в другое.

## Сборка

```sh
cd core && CGO_ENABLED=0 GOARCH=amd64 go build -trimpath -ldflags '-s -w' -o ../dist/sora-core ./cmd/sora-core && cd ..
cd macos/helper && CGO_ENABLED=0 GOARCH=amd64 go build -trimpath -ldflags '-s -w' -o ../../dist/sora-ctl . && cd ../..
packaging/engines/fetch.sh amd64 dist/engines
packaging/zapret/build.sh dist/engines
SORA_ARCH=amd64 SORA_VERSION=0.3.0 nfpm package --config packaging/linux/nfpm.yaml --packager deb --target dist/
```

`--packager rpm` и `--packager archlinux` собирают остальные форматы. CI
собирает пакеты job'ом `linux-packages` workflow `legacy.yml`: те же шаги,
что выше, плюс проверка состава всех трёх форматов; локально — теми же
командами вручную.

## Почему на Linux нет GUI

Графического клиента legacy для Linux нет и не планируется; это решение по
фактам стеков, а не вкуса:

- **Своих GUI-стеков у legacy два, и оба не про Linux.** Поставляемый клиент —
  WinForms на .NET Framework 4.8 (Windows); библиотека Control собирается и
  под net8.0, но UI в ней нет. Собираемого Flutter-дерева в legacy нет —
  есть только скелет `app/` (7 файлов, без `pubspec.yaml` и без единого
  экрана; GUI из него не собирается), а полноценное Flutter-дерево есть
  у основного поколения sora, у которого Linux GUI и пакеты приложения
  уже существуют; второй графический клиент в legacy дублировал бы
  основной продукт.
- **Новый GUI-стек в Go-ядре — тяжёлая новая зависимость.** Fyne, webview и
  GTK-биндинги тянут CGO, OpenGL/WebKit и мегабайты зависимостей в дерево,
  которое сознательно держится на чистом Go (`CGO_ENABLED=0`); веб-интерфейс
  из привилегированной службы расширил бы поверхность атаки ядра — отдельный
  непривилегированный веб-процесс ради одного экрана статуса того не стоит.
- **Вся поверхность управления уже существует и поставляется.** `sora-ctl` —
  тот же тонкий клиент, что обслуживает macOS-приложение: `status`,
  `import`, `servers`, `select`, `connect` (tun/proxy, `--kill-switch`),
  `disconnect` по production-сокету службы (legacycontrol JSON-RPC),
  один JSON-документ на команду, секреты — только в хранилище службы.
  Минимальный объём «статус / подключить / отключить / выбрать сервер из
  импортированных» им закрыт полностью и проверен живой установкой ниже.

Итого: форма legacy на Linux — служба + `sora-ctl`. Кому нужен графический
клиент на Linux — основной sora.

## Проверено живой установкой (2026-10-22)

Прогон LEGACY-FULL WS6 (отчёт `LEGACY-FULL-6-LINUX.md` в архиве отчётов):
пакеты собраны из чистого дерева (`git archive HEAD`), `.deb` установлен в
чистую rootfs Ubuntu 24.04 обычным chroot (без fakechroot), служба запущена
от пользователя `sora` с ambient-caps юнита и ответила по
`/run/sora/core.sock` (Handshake контракта 1.7, GetStatus). Подтверждены:
создание пользователя службы sysusers при установке; импорт сервера и
proxy-подключение со сквозным трафиком; TUN-подключение (интерфейс `sora0`,
policy-маршруты ядра, чистое отключение); отказ в доступе пиру вне группы
`sora` без polkit; purge-чистота (бинари, unit, `/var/lib/sora`, осиротевшая
таблица nftables). Kill switch на ядре песочницы отклонён guard'ом
fail-closed: ядро песочницы не поддерживает nft conntrack (любое `ct`-правило
отклоняется и на хосте), поэтому arm таблицы там невозможен; ruleset без
единственного `ct`-правила применяется и снимается от uid службы целиком.
Границы среды: systemd при загрузке в песочнице не стартует
(`systemd-nspawn` запрещён), служба запускалась с аргументами юнита вручную;
сквозной трафик через TUN требует второй сетевой namespace, а `setns` в
песочнице запрещён — поток данных через туннель доказан в proxy-режиме, для
TUN доказаны подключение, интерфейс и маршруты. rpm поставлен в alternate
root (payload и запуск бинарей), Arch — распаковка и запуск; нативных
rpm/Arch-систем в песочнице нет, их установочная проверка — на целевых
дистрибутивах.

Уточнение к прогону WS6: положительная polkit-ветка (допуск активной локальной сессии) — verify-on-machine: в контейнерном прогоне доказан только отказ по дизайну для пиров вне группы `sora`; rpm/Arch-скриптлеты построчно идентичны deb-скриптлетам, но в прогоне не исполнялись (исполнялись только deb-скриптлеты; rpm ставился в alternate root, Arch — распаковкой с чтением `.INSTALL`).
