# Частые вопросы

## Почему нет готового релиза?

Поставляемый клиент собирается в CI и проходит регрессионные проверки, но публичный релиз пока не выпущен. Что уже проверено и что осталось — в [legacy/PLANS.md](../legacy/PLANS.md).

## Почему переход по ссылке `sora://` ничего не делает?

Установщик регистрацию протокола уже делает, но зарегистрированный обработчик — поставляемый клиент, который аргумент `sora://…` не обрабатывает: переход пока молча игнорируется. Импорт подписки из ссылки реализован в новом клиенте; регистрация заработает без изменений, когда установочный комплект переключится на него. До тех пор добавляйте подписку вставкой ссылки в поле импорта.

## Windows 7 SP1 и 8.1 поддерживаются?

Конструкцией — да, запуском — пока не подтверждено. Клиент построен на .NET Framework 4.8, движки собраны под Windows 7, ядро — на Windows 7 SDK Go; но на самих Windows 7 SP1 и 8.1 клиент пока не запускался, и документация этого не заявляет. Все проверки выполнены на Linux и современной Windows в CI.

## Почему клиент не обновляется сам?

Самообновления у продукта нет сознательно: официальные сборки устанавливаются только из релизов вручную. Пункт проверки обновлений в интерфейсе открывает страницу релизов в браузере. Установка новой версии поверх старой сохраняет настройки и подписки.

## Что за новый клиент и почему он не поставляется?

Новый клиент (`legacy/Client`, .NET Framework 4.8, WinForms) собран, входит в репозиторий и проверяется интероп-тестами против настоящей службы ядра `SoraLegacyCore`, но в установочный комплект пока не включён. Смена комплекта — отдельная работа; пока она не сделана, поставляемым остаётся клиент на базе v2rayN.

## Почему установщик не подписан?

Подписи релизов установщика (minisign, Authenticode) пока не выпускаются: ключ подписи — действие владельца, до церемонии ключа установщик неподписан. Целостность встроенных в установщик компонентов при этом проверяется по SHA-256 до их запуска.

## Почему на Linux нет графического клиента?

Графического клиента legacy для Linux нет и не планируется: поставляемый клиент — WinForms для Windows, а полноценное Flutter-дерево с Linux GUI есть у основного поколения sora. На Linux поставляются служба ядра и клиент управления `sora-ctl` в пакетах .deb/.rpm/Arch. Полное обоснование — в [packaging/linux/README.md](../packaging/linux/README.md).

## Что с Android, macOS и iOS?

Для каждой из этих платформ в репозитории есть настоящее дерево клиента (`android/`, `macos/`, `ios/`), но готовых публичных релизов нет: Android существует как debug-APK ручной сборки, не проверенный на устройстве; macOS и iOS собираются и проверяются только на Mac владельца. Честный статус каждой платформы — в [platforms.md](../legacy/docs/platforms.md).
