# Если что-то не работает

Симптомы ниже — из поведения установщика и поставляемого клиента на текущем HEAD. Установка и удаление — в [install.md](install.md). К сообщению об ошибке прикладывайте безопасный диагностический архив из интерфейса, а не сырой журнал: в архиве нет подписок и учётных данных.

## Установщик предупреждает о недостающих обновлениях Windows 7

На Windows 7 SP1 установщик проверяет KB4490628 (стек обслуживания), KB4474419 (поддержка подписей SHA-2) и KB3140245 (TLS 1.2 в системном стеке) по установленным пакетам CBS. Если чего-то не нашлось, мастер до установки называет каждое обновление и то, на что оно влияет, и даёт выбор: отменить и сначала обновить Windows или продолжить.

Честная оговорка: обновление, пришедшее в составе накопительного пакета, записано под номером этого пакета, поэтому «не обнаружено» не всегда значит «не установлено» — для этого случая и нужен ручной выбор, а не жёсткий отказ. Без KB3140245 загрузка подписок по HTTPS на чистой Windows 7 SP1 может не работать: клиент включает TLS 1.2 кодом, но системный стек без этого обновления его не даёт.

## Установщик говорит, что нет .NET Framework 4.8

Установщик сам запускает встроенный установщик .NET Framework 4.8, предварительно сверив его SHA-256 с закреплённым значением; несовпадение прерывает установку — такой файл запускать нельзя, скачайте комплект заново из официального источника. На 32-битной Windows 7 перед этим так же проверяется и при отсутствии ставится KB3033929. Коды 3010/1641 означают, что для завершения нужна перезагрузка.

## Подписка не загружается

- Ссылка должна быть HTTPS: HTTP-подписка не сохраняется как успешно добавленная, интерфейс требует HTTPS.
- На Windows 7 SP1 проверьте KB3140245 (см. выше): без него системный TLS 1.2 недоступен.
- Неудачное обновление подписки не удаляет ранее сохранённые серверы — список серверов остаётся прежним, повторное обновление доступно из секции подписки.

## Переход по ссылке `sora://` молча игнорируется

Это известное честное состояние, а не поломка вашей системы: поставляемый клиент аргумент `sora://…` пока не обрабатывает. Вставьте ссылку подписки в поле импорта вручную — формат определится автоматически.

## После удаления остался включён системный прокси

Деинсталлятор при удалении запускает клиент с `--restore-proxy --silent` и переигрывает запись исходных настроек прокси, сделанную до первого изменения. Если прокси всё же остался, запустите установленный клиент вручную с `--restore-proxy` и подтвердите восстановление: код 0 — восстановлено или записывать было нечего; повреждённая запись честно сообщается ошибкой, а не молчаливой догадкой. Учитывайте: удаление стирает подписки и настройки поставляемого клиента в каталоге установки — перед удалением экспортируйте нужное из интерфейса.

## Служба `SoraLegacyCore` не отвечает

Этот установщик службу не ставит: поставляемый клиент запускает движки сам, и для его работы служба не нужна. Служба — путь нового клиента и разработки; она регистрируется самой службой (`sora-core --install-service`) и снимается командой `sora-core --uninstall-service`. Данные службы и нового клиента лежат вне каталога установки, в `%APPDATA%\sora-legacy\core`, и удаление клиента их не трогает.
