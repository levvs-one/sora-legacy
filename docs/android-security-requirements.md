# Требования безопасности Android-приложения (sora-legacy)

Дата: **19.10.2026**. Статус: **требования к новой разработке** — код Android-приложения
(`app/`) на момент аудита отсутствовал; пункты LEGACY-H6/H7/H8/M12/M13 из
`reports/FIX-PLAN.md` зафиксированы здесь как обязательные требования к разработке,
а не как исправления существующего кода.

Разработка `app/` ведётся другим агентом; этот документ — контракт, которому она
должна соответствовать. Приёмка каждого пункта — по критериям ниже.

---

## H6. UID-авторизация туннельного сервиса (P0)

**Проблема.** Декларация «команды только от приложения того же UID» существовала только
в README. При появлении сервиса любое приложение сможет слать intent-команды
(intent hijacking, принудительный disconnect туннеля).

**Требования.**
- В `onBind()`/`onStartCommand()` проверять `Binder.getCallingUid() == Process.myUid()`;
  чужой UID → отказ без выполнения команды.
- Только explicit intent'ы; не принимать implicit intent'ы для управления туннелем.
- Signature-level permission на управляющие intent'ы.
- `android:exported="false"` по умолчанию для всех компонентов сервиса.

**Приёмка.** Стороннее приложение не может вызвать старт/стоп VPN через intent
(тест с двумя разными UID: команды от чужого UID отклоняются).

## H7. Манифест приложения (P0)

**Проблема.** Манифест отсутствовал — неверифицируемы `exported`/`allowBackup`/cleartext.

**Требования** (при создании `AndroidManifest.xml`).
- `android:allowBackup="false"` (или `dataExtractionRules` с запретом выгрузки
  секретов и токенов).
- `android:exported="false"` по умолчанию для всех activity/service/receiver,
  кроме явно необходимых (launcher activity).
- `networkSecurityConfig` с запретом cleartext-трафика (`cleartextTrafficPermitted="false"`).

**Приёмка.** Ревью манифеста по чек-листу выше; `adb backup` не выгружает данные
приложения (секреты, токен, кэш плана).

## H8. Хранение `controlAuthenticator` (P0)

**Проблема.** Bearer-токен с полным контролем над ядром (эквивалент root для туннеля)
негде хранить безопасно: открытое хранение = компрометация при доступе к файлам.

**Требования.**
- Только Android Keystore-backed хранилище: `EncryptedSharedPreferences`
  / `flutter_secure_storage`. Никаких открытых SharedPreferences/файлов.
- Токен не попадает в логи, краш-репорты, бэкапы.
- После использования буфер с токеном зануляется в памяти.

**Приёмка.** Токен не встречается в SharedPreferences/файлах/логах/бэкапах
в открытом виде (проверка дампом данных приложения).

## M12. Канал UI ↔ ядро и bearer-URL в памяти (P0)

**Проблема.** Bearer-токен в памяти приложения без редектирующего хелпера;
gRPC без TLS — plaintext TCP на loopback, читаемый любым локальным процессом.

**Требования.**
- Центральная утилита редактуры URL: любой URL с токеном перед логированием/
  шерингом/отображением проходит через неё; сырой URL с токеном не покидает
  модуль хранения.
- Канал UI↔ядро: Unix-socket + `SO_PEERCRED` (проверка UID пира) либо TLS
  с пиннингом сертификата. Никогда plaintext TCP, даже на loopback.
- TLS без пиннинга недостаточен: локальный MITM через установленный CA.

**Приёмка.** Трафик UI↔ядро не читается сторонним локальным процессом
(перехват loopback не даёт plaintext); URL с токеном не попадает в логи/шеринг
(поиск по дампу логов).

## M13. Шифрованный кэш плана: дизайн ключей (P0)

**Проблема.** «Зашифрованный кэш» без key management — шифрование-фикция:
хардкод ключа в APK = отсутствие шифрования.

**Требования.**
- Ключ шифрования — только в Android Keystore; никогда в коде, ресурсах,
  SharedPreferences, BuildConfig.
- Direct Boot-aware хранение (`EncryptedFile` с `deviceProtectedStorage`
  по политике: кэш недоступен до разблокировки, если продукт того требует).
- Ротация/инвалидация ключа при смене блокировки экрана — по политике продукта.

**Приёмка.** Ключ не извлекаем из APK/бэкапа (реверс APK не даёт ключ);
кэш недоступен до разблокировки устройства (по выбранной политике);
удаление ключа делает кэш нечитаемым.

## Связь с Go-ядром

Ядро (`core/`) уже держит свою сторону контракта:
- Unix-socket с `SO_PEERCRED`-авторизацией пира (`core/ipc`);
- токен control plane как проверка живости клиента, транспорт — граница доверия
  (`core/control/auth.go`, см. LEGACY-H4);
- маскирование секретов и идентификаторов в диагностике и событиях
  (`core/engine` redactor, LEGACY-M3).

Android-приложение должно использовать тот же уровень строгости, а не слабее.
