# Безопасность

Что Sora Legacy хранит, что проверяет и чего не делает. Политика сообщения об уязвимостях — в [SECURITY.md](../SECURITY.md).

## Проверка движков — fail-closed

- Служба ядра сверяет бинари движков с дайджестами из поставляемого рядом `SHA256SUMS` при обнаружении движков. Несовпавший бинарь не запускается. Манифест отсутствует или нечитаем — движки по умолчанию не запускаются вовсе; флаг `-allow-unverified-engines`, ослабляющий это, выключен по умолчанию и предназначен для разработки.
- Комплект Windows собирается с проверкой: `legacy/build/Stage-Release.ps1` сверяет SHA-256 `xray.exe`, `sing-box.exe` и всех файлов `tun2proxy` с закреплёнными значениями до копирования в комплект.
- Установщик сверяет SHA-256 встроенных установщиков .NET Framework 4.8 и KB3033929 до их запуска; несовпадение прерывает установку.
- Обновление ядер из поставляемого клиента сверяет SHA-256 скачанного архива с `.dgst`-манифестом официального релиза до распаковки только для ядер v2fly, v2fly_v5 и Xray: не прошёл проверку — не распаковывается и не заменяет работающий бинарь. Для SagerNet (v2ray-core), clash и clash_meta такой проверки нет: апстрим не публикует `.dgst` в предсказуемом виде, сверка хеша пропускается, и для этих ядер действует только запрет downgrade. Ядро sing_box из интерфейса не обновляется вовсе.
- Самообновления у продукта нет: клиент не скачивает и не ставит новые версии самого себя.

Подписи релизов установщика (minisign, Authenticode) пока не выпускаются: ключ подписи — действие владельца, до церемонии ключа установщик неподписан.

## Хранение

- Ядро хранит подписки и секреты в зашифрованном хранилище: AES-256-GCM, отдельный nonce на запись. Ключ хранилища на Windows защищён DPAPI привязкой к учётной записи. Каталог данных службы по умолчанию — `%APPDATA%\sora-legacy\core` (Windows) и `~/.config/sora-legacy/core` (Linux); каталог создаётся с правами `0700`.
- Поставляемый клиент хранит свою конфигурацию в каталоге установки (`guiNConfig.json`, `guiConfigs`): это унаследованное поведение v2rayN. Учитывайте это при оценке модели угроз старой системы; удаление программы стирает эти данные (см. [install.md](install.md#удаление)).
- Настройки нового клиента — пользовательские параметры .NET (профиль пользователя), секретов среди них нет: подписки и ключи живут в хранилище службы, клиент получает от неё только нужное для отображения.

## Журнал и диагностика

- Журнал служба держит в памяти, на диск он не пишется. Секреты — UUID, пароли, ссылки подписок, токены — маскируются до записи в журнал и в диагностические архивы.
- Экспорт журнала и диагностики применяет то же маскирование. Перед публикацией экспортированного файла всё равно проверьте его глазами.

## Сеть

- Подписки ядро загружает только по `https://`. Ссылка с `http://` отклоняется: токен подписки не уходит открытым текстом.
- Телеметрии в ядре нет: служба не отправляет аналитику или статистику разработчикам. Сетевые обращения — загрузка подписок у провайдера пользователя; в поставляемом клиенте также, только по действию пользователя, проверка обновлений ядер и геобаз у официальных релизов на GitHub (GitHub видит IP-адрес и запрашиваемый релиз, как при обычном посещении сайта).
- Управление службой — локальное: named pipe на Windows и unix-сокет на Linux с проверкой вызывающей стороны и токеном управления; сетевых портов управление не открывает. Контроллеры движков слушают только loopback и с секретом на каждый запуск; конфигурация движкам уходит по stdin, а не файлом и не аргументами процесса.

## Kill switch

Ядро умеет kill switch: nftables на Linux, WFP на Windows. На Windows проверка живого поведения kill switch и TUN на старых системах не выполнена — совместимость с Windows 7 SP1 и 8.1 запуском ещё не подтверждена, и этот документ её не заявляет.
