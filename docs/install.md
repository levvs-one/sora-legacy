# Установка, обновление и удаление

Всё ниже — поведение установщика `legacy/installer/Sora.iss` и поставляемого клиента на текущем HEAD. Готового публичного релиза пока нет: этот документ описывает установщик, собранный по рецепту из [development.md](development.md), а не страницу загрузки.

Главное различие, которое нужно держать в голове: **поставляемый исполняемый файл — клиент на базе v2rayN** (`sora_<цель>.exe`). Новый клиент (`legacy/Client`) в установочный комплект не входит. Где поведение двух клиентов различается, это сказано явно.

## Требования

| Что | Минимум |
| --- | --- |
| Windows | 7 SP1 (по умолчанию; профили установщика для 8.1, 10 и 11 задаются при сборке) |
| Архитектура | x86; на x64 сборка работает через WoW64 (`ArchitecturesAllowed=x86compatible`) |
| .NET Framework | 4.8 |

Права администратора для самой установки не нужны: установка per-user. Повышение прав установщик запросит только для шагов .NET и KB ниже, если они понадобятся.

## Установка

Запустите `Sora-<версия>-<цель>-Setup.exe`. Мастер говорит по-русски и по-английски.

Куда ставится: `%LOCALAPPDATA%\Programs\Sora` (значение по умолчанию). Состав комплекта определяет `legacy/build/Stage-Release.ps1`: исполняемый файл клиента, `xray.exe` и `sing-box.exe` для режима TUN (комплект сверяет их SHA-256 с закреплёнными значениями и прерывает сборку при несовпадении), `tun2proxy` с `wintun.dll`, базы `geoip.dat` и `geosite.dat`, лицензии.

Что установщик делает по шагам (порядок — как в `PrepareToInstall` в `Sora.iss`: сначала KB3033929, затем .NET):

1. **На 32-битной Windows 7** проверяет KB3033929 (поддержка SHA-2 подписей). Если пакета нет — SHA-256 встроенного `.msu` сверяется с закреплённым в скрипте установщика, несовпадение прерывает установку; затем `wusa.exe /quiet /norestart` с повышением прав, при кодах 3010/1641 мастер предложит перезагрузку.
2. **Проверяет .NET Framework 4.8**: значение `Release` в `HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full` должно быть не меньше `528040` (проверяются обе ветки реестра на x64). Если 4.8 нет — запускается встроенный установщик .NET: сначала его SHA-256 сверяется с закреплённым в скрипте установщика, несовпадение прерывает установку; запуск — `/q /norestart`, при кодах 3010/1641 мастер предложит перезагрузку.
3. **Копирует файлы** комплекта в каталог установки.
4. **Регистрирует протокол `sora://`** на исполняемый файл комплекта (`HKCU\Software\Classes\sora`, обработчик — `"<exe>" "%1"`). Честная оговорка: поставляемый клиент аргумент `sora://…` сегодня не обрабатывает, переход по ссылке молча игнорируется. Импорт подписки из ссылки реализован в новом клиенте и заработает при смене комплекта; саму регистрацию менять не придётся.
5. **Ярлыки**: в меню «Пуск» — всегда; на рабочем столе и автозапуск — по флажкам мастера, по умолчанию оба выключены. Автозапуск от установщика — ярлык в папке автозагрузки пользователя с параметром `--silent`.

Службу `SoraLegacyCore` этот установщик **не ставит**: поставляемый клиент запускает движки сам. Служба — путь нового клиента и разработки; она регистрируется самой службой (`sora-core --install-service`), см. [development.md](development.md).

## Автозапуск: два механизма

- Ярлык установщика в папке автозагрузки (флажок «Запускать в фоне при входе в Windows»).
- Настройка «запуск при входе» внутри клиента: значение `SoraAutoRun_<MD5 каталога установки>` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, команда — `"<exe>" --silent`. Имя значения зависит от каталога, поэтому записью в скрипте установщика его не задать; деинсталлятор находит такие значения сканированием (см. «Удаление»).

## Командная строка поставляемого клиента

Контракт, который сегодня работает у пользователя (реализация — `Program.cs` поставляемого клиента). Новый клиент повторяет `--silent`, `--restore-proxy` и `--wait-for` и добавляет импорт по ссылке `sora://`; аргумент `--tun` новый клиент не обрабатывает — известное различие, см. абзац после таблицы:

| Аргумент | Поведение |
| --- | --- |
| `--silent` | запуск без окна, в трей |
| `--restore-proxy` | восстановить системный прокси, записанный до изменений Sora, и выйти. Код 0 — восстановлено или записывать было нечего; 1 — запись повреждена или применить не удалось. Без `--silent` сначала спрашивает подтверждение у пользователя |
| `--wait-for <pid>` | подождать завершения процесса с этим PID, не дольше 15 секунд, затем стартовать |
| `--tun` | стартовать с режимом TUN |

Один экземпляр на путь исполняемого файла: второй запуск не открывает второе окно, а активирует окно работающего экземпляра (адрес окна хранится в `HKCU\Software\Sora`) и завершается.

Различие нового клиента — `--tun`: такого аргумента в нём нет (ни в `ClientContract.cs`, ни в заголовке контракта в его `Program.cs`). Режим TUN новый клиент берёт из сохранённой настройки `ClientSettings.Tun` (по умолчанию включена), а не из аргумента запуска, поэтому после смены комплекта `sora_<цель>.exe --tun` будет молча проигнорирован. Контракты двух клиентов различаются ровно на `--tun` (только у поставляемого) и `sora://` (только у нового).

## Обновление

- **Самообновления у клиента нет.** Пункт проверки обновлений интерфейса просто открывает страницу релизов в браузере. Обновление продукта — ручная установка новой версии поверх старой.
- **Установка поверх**: запустите новый установщик в тот же каталог. Файлы комплекта заменяются. Файл конфигурации клиента `guiNConfig.json` в комплект сознательно не входит, поэтому установщик его не перезаписывает; каталоги данных клиента (`guiConfigs` с подписками и серверами, `guiBackups`) установщик при установке не трогает — настройки и подписки переживают обновление.
- **Движки из интерфейса**: поставляемый клиент умеет обновлять ядра (Xray, sing-box и другие из своего списка) и геобазы с официальных релизов. Архив ядра до распаковки сверяется по SHA-256 с `.dgst`-манифестом релиза только для ядер v2fly, v2fly_v5 и Xray; несовпадение — отказ, бинарь не заменяется. Для sing-box (SagerNet), clash и clash_meta `.dgst`-манифеста у апстрима в предсказуемом виде нет, поэтому проверка хеша для них пропускается (остаётся запись в журнал) и действует только запрет downgrade. Движки, которые запускает служба ядра, проверяются строже: служба сверяет каждый бинарь с дайджестом из поставляемого `SHA256SUMS` при каждом обнаружении и не запускает несовпавший.
- **Данные службы ядра** (настройки нового клиента, зашифрованное хранилище подписок и секретов) лежат вне каталога установки, в `%APPDATA%\sora-legacy\core`, и установка поверх их не касается.

## Удаление

Удаление — стандартное, через «Программы и компоненты» или `unins000.exe` в каталоге установки. Деинсталлятор:

1. **Восстанавливает системный прокси**: запускает клиент с `--restore-proxy --silent` и ждёт завершения. Поставляемый клиент переигрывает запись `user-wininet.json`, которую сделал до первого изменения прокси (флаги подключения, сервер, список исключений, PAC-URL), через bundled `sysproxy.exe` и удаляет запись. Не было записи — восстанавливать нечего, это успех. Повреждённая запись — ошибка, молчаливой догадки нет.
2. **Снимает регистрацию `sora://`** целиком (ключ протокола помечен на удаление при деинсталляции).
3. **Удаляет осиротевший автозапуск**: сканирует `HKCU\…\Run`, удаляет только значения `SoraAutoRun_*`, чья командная строка указывает на исполняемый файл именно этой установки. Значения, указывающие в другой каталог (другая копия Sora), не трогает. Ярлык автозагрузки из папки автозагрузки удаляется как установленный элемент.
4. **Удаляет данные поставляемого клиента в каталоге установки**: `guiNConfig.json`, `statistics.json`, `guiLogs`, `guiTemps`, `guiBackups`, `guiConfigs`. Следствие, о котором честно предупреждаем: **подписки и настройки поставляемого клиента удаление не переживают** — в отличие от обновления поверх. Перед удалением экспортируйте нужные подписки из интерфейса.
5. Не трогает `%APPDATA%\sora-legacy\core` (данные службы ядра и нового клиента) и саму службу `SoraLegacyCore`, если вы регистрировали её вручную: она снимается командой `sora-core --uninstall-service`.

### Ограничение восстановления прокси в новом клиенте

Когда комплект переключится на новый клиент, его собственное восстановление (`--restore-proxy`, нативная реализация без `sysproxy.exe`) будет работать с двумя честными ограничениями, зафиксированными в его коде: восстанавливаются именованные значения HKCU Internet Settings, включая PAC-URL, но **бит AUTO_DETECT не восстанавливается** (он живёт только в бинарном `DefaultConnectionSettings`, который восстановление сознательно не переписывает), а **per-connection записи RAS не переигрываются** (поставляемый путь через `sysproxy.exe` применяет настройки шире). До смены комплекта пользователю работает поставляемый путь из пункта 1 выше.
