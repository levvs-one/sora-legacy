# Участие в разработке

## Как устроена работа

Участие в проекте регулируется [кодексом поведения](CODE_OF_CONDUCT.md).

- Одна задача в одном pull request. Pull request меняет только тот каталог и тот слой, к которому относится задача.
- Ветка называется по задаче, например `wo-58-proto`.
- Pull request сливается только после прохождения всех проверок в CI.
- Изменение поведения сопровождается тестом. Исправление ошибки сопровождается тестом, который падал до исправления.

## Правила кода

- Ошибки не подавляются. Каждая перехваченная ошибка либо обрабатывается явным восстановлением, либо превращается в `SoraError` из каталога ошибок.
- Секреты никогда не попадают в журналы, события и отчеты: адреса серверов, UUID, пароли, ссылки подписок и токены проходят через фильтр маскирования.
- Зависимости фиксируются по версии и контрольной сумме.
- Форматирование задается `.editorconfig` и настройками линтеров в каждом каталоге: `gofmt` и `golangci-lint` для Go, `dart format` и `analysis_options.yaml` для Dart, `ktlint` для Kotlin.

## Правила интерфейса

- Иерархия задается типографикой. Надзаголовки над заголовками, текст капсом и декоративные значки не используются.
- Статус передается текстом и одним сдержанным цветовым сигналом, без плашек-капсул.
- Средняя точка и похожие символы не используются как разделитель элементов. Элементы разделяются расстоянием, переносом строки или отдельными строками списка.
- Градиенты, свечения и декоративная анимация не используются. Анимация показывает только смену состояния и учитывает системную настройку уменьшения движения.

## Клиенты каталога `legacy/`

Правила ниже относятся к поставляемому клиенту на базе v2rayN и новому клиенту в каталоге `legacy/`; общие правила выше действуют для всего репозитория.

- Целевая платформа приложения — `net48/win7-x86`. Новая зависимость должна поддерживать .NET Framework 4.8 и Windows x86.
- Интерфейс остаётся монохромным: чёрный, белый и нейтральный серый без цветовых акцентов. Новые экраны не должны использовать стандартные светлые элементы WinForms.
- Нельзя коммитить `bin`, `obj`, пользовательские конфигурации, журналы и собранные установщики.
- Изменение поведения поставляемого клиента описывается в корневом `CHANGELOG.md`.

Проверка поставляемого клиента:

```powershell
dotnet restore .\legacy\v2rayN\v2rayN\v2rayN.csproj --runtime win7-x86
dotnet build .\legacy\v2rayN\v2rayN\v2rayN.csproj --configuration Release --runtime win7-x86 --no-restore
```

Перед pull request проверьте чистый запуск, импорт конфигурации, выбор сервера, системный прокси, TUN, журналы и удаление приложения.

Отправляя изменение, вы соглашаетесь распространять его по GNU GPL-3.0 вместе с остальным проектом. Сохраняйте уведомления об авторстве и лицензии сторонних компонентов.

## Sora Legacy

Правила сборки Sora Legacy описаны в [legacy/CONTRIBUTING.md](legacy/CONTRIBUTING.md). В Legacy принимаются только исправления безопасности и критических ошибок.
