# Изменения

## Не выпущено

## 0.2.4 (23 октября 2026)

- Интерфейс всех клиентов стал чище: WinForms-клиент, клиент для старых Windows, Android, iOS и macOS, v2rayN. Подписи и статусы написаны обычными словами, режимы подписаны, имя выбранного сервера и формы импорта не теряются на фоне, вместо пустых полос показывается состояние. В клиенте для старых Windows отказ называет причину одним предложением.
- sora-ctl и службы: отказ службы называет причину понятной фразой (`core/errs`) вместо внутреннего ключа, в том числе самый частый — «служба недоступна». Имя Sora Legacy одинаково в журнале событий Windows и в текстах пакетов.
- Сборка v2rayN из исходников работает и на файловых системах с учётом регистра: исправлены пути семи ресурсов (`resources` → `Resources`), а шаг после сборки выполняется только на Windows (MSB3103 и MSB3073). На Windows сборка не меняется.
- CI сверяет версии движков с минимальными версиями каталога (`tools/check-engine-pins.py`); тесты производительности проходят 22 из 22.
- Документация сокращена: убраны служебные пояснения и повторы, факты и ограничения платформ сохранены.
- Android: `versionName` следует версии продукта, а `versionCode` выводится из неё единым правилом (major*10000+minor*100+patch) в Gradle-конфиге и ручном пайплайне; значение на этом релизе — 0.2.4 / 204; оба тира (minSdk 21 и аддитивный API 19) несут один код.
- Версия продукта сведена к единому значению 0.2.4 во всех build-источниках, включая CI Linux-пакетов (`legacy.yml`).

## 0.2.3 (22 октября 2026)

Первый выпуск объединённого репозитория. Более ранняя запись 0.2.3 ниже (31 августа 2026) — выпуск прежнего отдельного клиента.

- Клиенты всех платформ в одном дереве: Windows XP SP3, Vista SP2 и 8.0 (.NET 4.0 и 4.6, движок v2ray-core v3.36, проверено под Wine), Android 5.0 и новее (APK собран) и отдельная сборка для Android 4.4, macOS (служба с 12.0, движки с 11.0 и 10.15), iOS 13 и отдельная сборка для iOS 12. Установка пакета Linux проверена в чистой системе, служба отвечает по контракту 1.7.
- Качество: общий набор из 167 ссылок проверяет, что sora и legacy разбирают их одинаково (64 разбора совпадают побайтно, 103 одинаково отклоняются); полнота переводов проверяется тестом; тесты производительности проходят 22 из 22; описание сервера в памяти занимает 424 байта вместо 840.
- Ядро: версии движков, которые нужны для ECH `query_server_name` (sing-box 1.13 и новее) и полей Hysteria2 (1.14 и новее), закреплены тестами выбора движка; отпечаток TLS проверяется по каталогу до подключения; очистка журналов подтверждена на всех 31 языке нового клиента.
- Оформление: README и его английская версия, единый набор служебных файлов, мастер установки Inno на русском и английском, логотип на Android, Apple и в клиенте для старых Windows, окно «О программе» называется Sora Legacy.
- Версия продукта сведена к единому значению 0.2.3 во всех build-источниках, включая CI Linux-пакетов (`legacy.yml`).

- Перенесён старый клиент Sora Legacy в `legacy/`.

- Контракт ядра — `sora.core.v1`, текущая версия **1.7**:
  `core/cmd/sora-core/main.go` задаёт `Version{Major: 1, Minor: 7}`, а
  `proto/README.md` фиксирует, что 1.7 добавляет явный TUN-стек в
  `SessionPlan`.
- Общий фундамент мобильных и Apple-платформ — `core/mobileapi`
  (gomobile-фасад ядра: `ImportLinks`, `ParseSubscription`, `BuildPlan`,
  `RenderSingBoxConfig`, `EngineInfo`); пайплайн внутри десктопный
  (`parser` → `control` → каталог движков → рендер sing-box), а не
  переписанный под мобильные платформы.
- Два фикса ядра, на которых стоят мобильные клиенты: нормализация
  транспорта WireGuard в `control.outboundFromProto` (написания `""`,
  `"tcp"`, `"udp"` → пустой транспорт, остальное — именованная ошибка) и
  гейт ECH `query_server_name` — поле выдаётся только сборкам sing-box
  ≥ 1.13, поэтому на payload-пине 1.12.12 план с этим полем отклоняется
  до рендера.

- Настройки Hysteria2/TUIC проводятся от импорта через план и гейты до
  конфигов движков; ECH и REALITY `key_share` рендерятся и гейтятся по
  движкам; поля XHTTP `extra=` (включая xmux и padding) проводятся
  сквозным путём.
- Классические ссылки `vmess://` (base64-JSON) импортируются сквозным
  путём; поддержан `fallback-url` подписок и хранение/применение
  override-подписки.
- olcRTC — **только импорт**: ссылки `olcrtc://` разбираются, креды
  переживают хранилище, а построение плана честно отказывает с именем
  протокола — рантайм-транспорта olcRTC в legacy нет ни на одной
  платформе (PARITY, строка olcRTC: «частично — только импорт» везде).

- Локальный скрипт сборки ядра для
  Windows 7 — двойник CI (тот же go-win7 SDK, SHA-256 и проверка версии
  из `core/go.mod`); обычный `go build` даёт пол Windows 10, о чём
  предупреждает `docs/development.md`.
- поддержка Windows 7 SP1 и 8.1 везде, где она обещается, помечена
  как целевая конструкция (.NET Framework 4.8, Win7-движки, ядро на
  Windows 7 SDK Go), а **не** как подтверждённый запуском факт — на самих
  этих системах клиент пока не запускался.
- установщик на Windows 7 гейтит KB4490628, KB4474419 и KB3140245:
  отсутствующие обновления называются поимённо, и пользователь выбирает
  — обновиться сначала или продолжить.
- в `legacy/PLANS.md` набор движков CI нового клиента разведён с
  поставляемым payload установщика (на тот момент payload-Xray был
  25.9.11; позже он поднят до 26.3.27 — см. ниже).
- CI собирает Linux-пакеты (job `linux-packages`: ядро, движки,
  zapret, nfpm; содержимое .deb/.rpm/Arch проверяется).
- Два пункта из того же списка из этого репозитория **не закрыты**: их
  файлы находятся в репозитории основного поколения sora; для них
  оставлен готовый рецепт фикса, а не заявление о закрытии.

- **Android** — настоящее дерево `android/`: нативный клиент на
  framework Views без AndroidX/Compose, `minSdk 21` / `targetSdk 34`,
  движок — libbox из sing-box 1.12.12 через `SoraVpnService`, полная
  реализация `PlatformInterface` пина (18 методов). APK реально собран
  ручным офлайн-пайплайном: 279 213 197 байт (~266 MiB), подпись —
  debug-ключ. На устройстве трафик и VPN-флоу **не проверены**
  (verify-on-device).
- **macOS** — настоящее дерево `macos/` плюс служба `service/darwin`:
  корневой LaunchDaemon, AppKit-клиент (дизайн-пол 10.13) и Go-хелпер
  `sora-ctl`, говорящий с демоном его штатным `legacycontrol` JSON-RPC
  по unix-сокету. Измеренный пол демона и хелпера — **macOS 12.0**.
  Kill switch на darwin **не форсится**: `core/guard` возвращает там
  `NoopFirewall`, клиент показывает «requested, NOT enforced».
  Сборка и запуск на Mac **не проверены** (verify-on-mac).
- **iOS** — настоящее дерево `ios/`: UIKit-приложение, расширение
  PacketTunnel и SPM-пакет `SoraLegacyCore`; движок — `BoxService` пина
  sing-box 1.12.12, `PlatformInterface` реализован полностью (18/18).
  Пол — **iOS 13.0**, выведен из пина, а не назначен. Сборка в Xcode и
  туннель проверяются только на Mac/устройстве.
- Linux в этом поколении — служба ядра плюс CLI-клиент `sora-ctl`, без
  графического клиента; пакеты .deb/.rpm/Arch собираются из
  `packaging/linux`, движки закреплены в `packaging/engines/engines.lock`

- **Древний трек Windows** — отдельное дерево `ancient/`, основной стек
  не меняет: клиент на одних исходниках в сборках `net40` (XP SP3) и
  `net46` (Vista SP2 / Windows 8.0), движок v2ray-core **v3.36**.
  Режимы — только прокси (SOCKS 10808 + HTTP 10809, системный прокси);
  **TUN нет и не обещается**. Протоколы по пробам бинаря: VMess,
  Shadowsocks, SOCKS; VLESS, Trojan, Hysteria, TUIC, WireGuard, SS-2022,
  REALITY/XTLS и QUIC на импорте честно отказывают. Runtime проверен под
  Wine в обоих префиксах (движок и клиент стартуют, loopback-трафик
  получен); Wine не доказывает драйверы и сетевые стеки самих ОС.
- **Payload-Xray поднят с 25.9.11 до 26.3.27** — ровно пол каталога
  (`MinVersion` в `core/engine/catalog.go`). Причина измерена бинарями

  для darwin arm64+amd64 с полом **11.0**, sing-box 1.11.15 (amd64) — с

> не описывает sora-legacy.** Ниже без изменений сохранён прежний текст
> раздела «Не выпущено»: он датируется коммитами основного поколения от

> например, аудитов от 02.10.2026) и описывает состояние основного

> 1.3 и функции, которых в sora-legacy в таком виде нет. Актуальное
> невыпущенное состояние sora-legacy — только в подразделах выше.

- Подписки живут в ядре и обновляются сами, даже при закрытом интерфейсе:
  интервал свой, от панели или раз в сутки; после ошибки повтор с нарастающей
  паузой, а последний рабочий список серверов остаётся. Обновление переживает сон
  компьютера, двойной запуск и удаление подписки посреди загрузки. Список серверов,
  ключи и запись подписки пишутся в хранилище одной операцией.
- Свой User-Agent на подписку и информация от панели: название, трафик и срок,
  интервал обновления, ссылки на сайт и поддержку, объявление.
- Пакеты .deb, .rpm и для Arch Linux с закреплёнными по SHA-256 ядрами; служба
  ставится и запускается без терминала, доступ из активной сессии — через polkit.

- Ядро запускает три движка — sing-box, Xray-core и mihomo — через общий
  супервизор и для каждого плана выбирает первый, который проводит план целиком:
  XHTTP и VLESS Encryption уходят в Xray, fallback-группы в mihomo, остальное в
  sing-box. Флаг `-engine` закрепляет один движок.
- Движок sing-box переписан под формат 1.12+: конфигурация только по stdin,
  секрет контроллера из `crypto/rand`, группы, действия маршрутизации, WireGuard
  как endpoint, geo-правила как rule set, REALITY с uTLS, AnyTLS.
- Добавлен движок Xray-core: XHTTP, VLESS Encryption, балансировщики,
  измерение задержки настоящим запросом через отдельный процесс.
- Добавлена фрагментация TLS ClientHello против DPI для sing-box и Xray.
- Добавлен AmneziaWG (1.x и 2.0) через mihomo: импорт `.conf` со всеми
  параметрами (Jc, Jmin, Jmax, S1–S4, H1–H4 с диапазонами, I1–I5, J1–J3, Itime).
- Пинг в режиме «авто»: каждый сервер меряется настоящим запросом через ядро,
  которое его проводит, а где такого ядра нет — подключением; в результате
  указано, каким способом и через какое ядро. Метод, адрес проверки, таймаут,
  параллельность и порядок ядер задаются в запросе.
- Порядок ядер настраивается для каждой сессии (`SessionPlan.engines`).
- Центр логов: служба и все ядра в одной записи только в памяти, фильтры по
  уровню, источнику, тексту, регулярному выражению и времени, живой просмотр,
  свёртка повторов, статистика, выгрузка в текст, JSON Lines и CSV, очистка.
  Уровень записи меняется сразу, без переподключения; адреса посещённых сайтов
  по умолчанию скрыты.
- Центр соединений: живой список соединений сессии с правилом, цепочкой и
  трафиком, закрытие отдельного соединения (mihomo, sing-box).
- Логи и соединения выдаются только по токену управления.
- Другие приложения не видят Sora через порты: в режиме tun прокси-порт не
  открывается, «прокси для других приложений» включается явно и закрывается
  логином, а управление ядром по умолчанию идёт через unix-сокет или named pipe
  без единого TCP-порта.
- Базы geoip и geosite берутся из комплекта Sora, mihomo больше не качает их
  при первом подключении.
- Исправлено в движке mihomo: пути и host у ws, grpc, h2, httpupgrade и xhttp
  терялись, WireGuard писался ключами, которых mihomo не знает, VMess не
  запускался без `alterId`, группа не могла включать другую группу.
- Контракт `sora.core.v1` поднят до 1.3: `SessionPlan.anti_censorship` включает
  фрагментацию, `SessionPlan.engine` закрепляет движок сессии. Возможности
  `engine-selection` и `tls-fragment` объявляются в handshake.
- Исправлено: ключ REALITY, путь и host транспорта, режим XHTTP и ALPN
  сохранялись при импорте, но не доходили до движка; серверы REALITY, ws и grpc
  не подключались.
- Исправлено: приватный ключ, адреса интерфейса и пиры WireGuard из `.conf` и
  ссылок `wireguard://` не доходили до движка; пароль obfs у Hysteria2 терялся,
  если ссылка писала его как `obfs-password`.
- Исправлено: префиксы правил `domain:` и `full:` были перепутаны, а префикс
  `geosite:`/`geoip:` оставался внутри значения правила.

- Определен versioned gRPC-контракт `sora.core.v1` с генерацией Go и Dart.
- Добавлены contract tests для handshake, событий и безопасных ошибок.
- Добавлен каталог ошибок ядра: код класса отказа, ключ локализации и
  маскированная деталь вместо пользовательского текста внутри ядра.
- Добавлено шифрованное хранилище секретов: AES-256-GCM, ключ под защитой DPAPI
  на Windows, атомарная запись и идентификатор хранилища, связанный с
  шифротекстом.
- Добавлена машина состояний сессии с супервизором, backoff, бюджетом рестартов
  и журналом событий с воспроизведением по номеру.
- Добавлен control plane поверх `sora.core.v1`: согласование версии, проверка
  аутентификатора в постоянном времени, лимиты запроса и все методы контракта.
- Добавлена проверка серверов без туннеля: ограниченная параллельность, поток
  результатов по мере готовности и отсутствие адресов в ответе.
- Добавлено управление системным прокси: на Windows состояние ключа реестра
  читается до записи и возвращается потом, включая случай «прокси был выключен».
- Добавлен kill switch на Linux: собственная таблица `nftables`, которая пропускает
  движок, локальную сеть и уже установленные соединения, а всё остальное
  отбрасывает.
- Добавлена загрузка подписки: только https, ограниченное число редиректов с
  проверкой каждого перехода, ограничение тела и никакого кэша, потому что тело
  подписки — это список учётных данных.
- Добавлена диагностика: отчёт и zip-архив, собираемые только из уже
  маскированных значений; имена серверов теперь тоже маскируются, потому что
  отчёт с названием провайдера — это отчёт о конкретном человеке.
- Добавлен локальный транспорт ядра: именованный канал на Windows и unix-сокет на
  Linux и macOS, оба без порта и недоступные с других машин.
- Контракт дополнен методами `PutSecret` и `DeleteSecret`, а также кодами ошибок
  `PERMISSION_DENIED` и `CANCELLED`.

## 0.2.3 (31 августа 2026)

- Подписки находятся прямо на экране серверов и отображаются отдельными сворачиваемыми секциями.
- Название, описание, лимит трафика, срок действия, обновление и проверка задержки относятся к конкретной подписке.
- Список серверов стал плотнее и показывает страну, протокол, транспорт, безопасность и результат проверки.

- Прямой импорт ссылки, Base64, SIP008 или Xray JSON больше не прикрепляет серверы к соседней подписке.
- Ранее импортированные серверы без принадлежности переносятся в отдельную локальную подписку.
- Повторный импорт, восстановление системного прокси и сохранение режима подключения больше не оставляют противоречивое состояние интерфейса.

## 0.2.2 (29 августа 2026)

- Проверка задержки использует прямое TCP-соединение с адресом сервера и больше не зависит от доступности Google или запуска временного прокси.
- Временные сетевые ошибки при загрузке подписки обрабатываются повторной попыткой через Polly.Core.

- Подписки, возвращающие массив полных конфигураций Xray, распознаются и импортируются отдельными серверами с исходными названиями.
- Несовместимые с Xray протоколы внутри смешанного массива пропускаются и не создают заведомо нерабочие записи.
- Поле импорта принимает до 4 МБ и больше не обрезает крупные подписки на 32 КБ с последующим ложным определением формата.
- Неудачное обновление подписки не удаляет ранее сохранённые серверы и конфигурационные файлы.
- TCP-пинг работает для импортированных конфигураций Xray и показывает состояние проверки для каждой строки.
